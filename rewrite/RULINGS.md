# Rulings

Decisions on points the specs or the inventories left open. Newest last. A ruling changes a spec
file in the same commit when it contradicts one.

| # | Date | Question | Ruling | Why |
|---|---|---|---|---|
| R1 | 2026-11-11 | What is a number in the IR: the source simulator's double, or the correctly rounded decimal? (`INV-semantics.md` 1.08; ledger P3-133 against P3-105 and D15) | Neither: the decimal literal as written (`IR-KERNEL.md` §7.3). | The source's double is exact on the same simulator and unreadable everywhere else; the rounded decimal is one ulp off on the same simulator, which moves ngspice's time steps (1.09). The literal gives both: the same digits make the same simulator compute the same double, and `100u` stays `100u` across dialects. Readers do no floating arithmetic. |
| R2 | 2026-11-11 | How does a reader state a simulator's own meaning of a function, a law or a default? | As a node, a law field, a mode field or an explicit field; never as an idiom built from other nodes (`IR-KERNEL.md` §7.1, `IR-CIRCUIT.md` §1). | A reader and its writer must be inverse on their own dialect (law L5). `Ln(Abs(x))` written by the ngspice writer reads back as `LnAbs(Abs(x))`: the idiom breaks the inverse, the member does not. Conversions are passes, each proved once with the reference evaluator. |
| R3 | 2026-11-11 | Who binds references? | A dialect reader, by its own simulator's rule. Builders and the IR text parser call the neutral `link` (exact names, innermost scope first). An instance of an unresolved master is never linked: binding it also decides its kind, which needs the kit and belongs to the reader that has it. | Scoping and case rules differ per simulator; a neutral linker applied to a deck read from a dialect would be a pair rule in disguise. |
| R4 | 2026-11-11 | `link` leaves a reference unbound: silent or noted? | Silent. An element's master expects one definition kind, given by its `ElemKind`. | Unresolved is legal (the kit may be absent); whoever needs the count asks the design. A reader that wants a note writes its own, with its own code. |
| R5 | 2026-11-11 | Xyce and a dot line that starts with a blank (`INV-semantics.md` 14.03: the manual-based code drops it, a 7.10 run reads it) | The run wins: the Xyce reader reads it. Settled again by a run in the Xyce slice before the reader fixture is written. | The simulator is the oracle of its own dialect; a manual is the fallback when no run exists. |
| R6 | 2026-11-11 | ngspice level-3 diode mask offset: `xw` or `xom` (`INV-semantics.md` 6.27) | `xw`, as the cited source (`dio/diosetup.c:304-305`) reads; checked against ngspice in the ngspice slice. | One side cites the source line, the other does not. |
| R7 | 2026-11-11 | `sdt`/time integral on ESPice (`INV-semantics.md` 2.18: one settle file says translate by run, another refuse) | Open until the ESPice flavour's slice: one run on the pinned ESPice decides, and the feature set states the result with the run as its citation. | Two files disagree and both claim evidence. |
| R8 | 2026-11-12 | The gaps listed in `COVERAGE-circuit.md` (G1–G28) and `COVERAGE-run.md` (G-…): typed now, or later? | The proposals stand as written. A gap gets its typed row in the slice of the second dialect that has the meaning (that slice's Plan phase names it; the row's owner adds it as an amendment). Until then its reader emits an `Opaque` of the class the proposal names. HB per-tone drive (G8, G-HBDRIVE) is a circuit-owned side row on the source; `xfmag` (G13, G-XFMAG) is a source field. | One dialect alone loses nothing with a `Private` opaque (its own family copies the text). A typed row pays only when a second dialect reads or writes the meaning, and its shape is known only then. |
| R9 | 2026-11-12 | The facade meets a new code with no row in `OLD_CODE`: which old code? | One of two rows added to the old catalogue for this (a note and a refusal, "a diagnostic of the IR pipeline", the message carrying the new code and title), chosen by the new row's verdict. No fallback by letter and number. `OLD_CODE` holds a row only where a routed test asserts an old code. | Codes are renumbered once (REWRITE-PLAN §10); an accidental number match is a wrong code with no crash. A refusal must stay a refusal. |
| R10 | 2026-11-12 | Who reports the leftovers of `legalize`, and a strict read's `Unread` items? | `ir::check_legal` reports the leftovers (one `U` row per item and feature, at the item); the spine adds none of its own. `Policy::Strict` is the spine's rule, so its code is a row of the spine's own table. Attribution of an item to a file is by its listing scope (`Design::reachable`), never by its span. | One owner per fact: the IR knows which item uses which feature; the spine knows the caller's policy. Spans are cold and may be absent. |
| R11 | 2026-11-12 | `dialect::write` legalized the whole design for every file it wrote (SPINE §3 as first written): a kit of N files paid N clones and got each refusal N times. | `dialect::legalize(design, to, diags)` runs once per (design, target), in place; `write` takes a legal design and only calls the writer (legality is a debug assertion there). A foreign `Opaque` of class `Inert` is dropped with a note by `legalize`; every other foreign class is refused. Legality is of the whole design. | Granularity: the caller must be able to do the per-design step once and the per-file step N times. An inert statement moves no number, so dropping it is exact; the old pipeline writes such decks, and refusing them would be a regression with no gain. |
| R12 | 2026-11-12 | ngspice-45's B-source `ln(0)` is −1e99, `exp` clamps at 1e99, `ln` of a negative is an error: is that part of `Ln`/`Exp`? And `INV-semantics.md` 2.07 (B-source `ln`/`sqrt` of \|x\|, `exp` linear past 14) against the source (`ptfuncs.c:275-326`) and runs. | The source and the runs win: default-mode ngspice-45 reads B `ln`/`log` as `Ln`, `sqrt` as `Sqrt`, `exp` as `Exp`; `ExpLin14` is its `ngbehavior=ps` mode (a flavour, later slice). What a function does outside its domain is not part of a member's meaning and is not carried. | The simulator is the oracle of its own dialect (R5). A deck that leans on a saturation value is ill-posed on every simulator; carrying each simulator's out-of-domain value would multiply every member. |
| R13 | 2026-11-12 | When may a reader lower a spelling to a tree of other nodes (ngspice `a\b` = trunc(\|a/b\|), `u2`, `sqr`, `pwr`), given R2 forbids idioms? | Sugar is allowed only when (a) the tree equals the source on the whole domain, same operations in the same order, (b) every operand appears exactly once, and (c) the reader's own writer spells that tree so that it reads back as the same tree. Otherwise the meaning is a member, added by the kernel owner on request (definition with domain, speaker with citation, evaluation points). An expression has no `Opaque`: a function a simulator has is a `Func` member. | (c) is law L5, which R2 protects. (b): an operand may hold a draw, and IR text has no shared rows. A parameter kept as text loses every reference to it, so the statement-level `Opaque` is not a home for an unknown function. |
| R14 | 2026-11-12 | The static/dynamic feature split tested V, I, Time, Freq syntactically; ngspice evaluates every expression that depends on `temper`, directly or through a parameter, with its B-source evaluator, whose functions differ. | An expression is dynamic when it, or a parameter or user function it reads transitively, holds V, I, Time, Freq, Temp, Ddt or Idt. `ProbeContext` is unchanged. | A writer's feature set says which functions it spells in which evaluator; the class must follow what the target will evaluate where, or a writer is handed a static `Pow` its simulator runs as `PowAbs`: a wrong number with no crash. Single-evaluator dialects have equal sets and lose nothing. |
| R15 | 2026-11-12 | A reader meets a statement with no meaning left (ngspice `.global gnd`, after `gnd` → `0`). Dropped? | Kept as an `Opaque` of class `Inert`. | L1 (every statement in is an item out) holds with no special count; the same family copies it, another drops it with a note (R11). |
| R16 | 2026-11-12 | VACASK's arithmetic is typed: `1/3` is 0, and `x/2` truncates or not by the type of the value an instance passes (DIALECT-VACASK runs i1, t3, f2). Typed in the IR, or resolved by the VACASK reader? | In the IR: an `Int` literal form, a tag on every value, `DivTyped`, `ToInt` (AMEND-A12 K1). `Div` stays real division; the VACASK reader always reads `/` as `DivTyped`; passes do the typing. | The type follows the value, so a reader cannot decide it for a library (a subcircuit with no instance yet); a kit is a first-class input. The old pipeline copies `/` as text and gives wrong numbers both ways. |
| R17 | 2026-11-12 | Every VACASK device needs a `load` of the simulator's own library file and a `model` line; a writer that invents them breaks L5, a pass that adds them cannot know file names. | A typed item, `DeviceLibrary { family, path }` (`path` absent = the target's default file), and features for "a model with no library of its family" and "an element with no model"; neutral passes add and remove them (AMEND-A12 C5). | Explicit over implicit: the reader and the writer stay inverse, and the pass knows families, not file names. |
| R18 | 2026-11-12 | R8 read narrowly ("typed at the second dialect") would keep VACASK's pulse law, its DC rule and `elaborate` opaque and refuse decks the old pipeline writes. | R8 means: a meaning is typed when a second dialect **or a pass** must read or write it. `Opaque` is the home only of what no conversion touches. | The point of R8 is not to guess a shape before its second use; a pass is a second use. |
| R19 | 2026-11-12 | Solver-only options of one simulator (`tran_lteratio`, `nr_*`, `homotopy_*`): refused off their simulator, or dropped? | A sixth class, `OpaqueClass::Hint`: tunes the solver, names no accuracy target; another family drops it with a note. The reader classifies. An option that scales an accuracy target (`tolscale`) is `Private`, not a hint. | Dropping it leaves a valid simulation on the target's defaults; refusing would be a regression on corpus decks with no gain. `Inert` would be a lie: the numbers may move within tolerance. |
| R20 | 2026-11-12 | Is a `Dc` over an axis the same meaning as a `Loop` of a sweep around one `Op`? | Two meanings: one result over the grid, each point continued from the last, against one result per value. A target that spells both the same lacks `LoopOverOp` and a pass converts; giving the results back in the source's shape is the run side's job (S12). | The result's shape is what the caller reads back. |
| R21 | 2026-11-12 | A target simulator rejects (VACASK) or silently ignores (ngspice) a model parameter its module does not have. No feature can list every simulator's parameter sets, and L4 says a writer refuses nothing. | `Write::admits(design, diags)`: the dialect's own legality check, called last by `legalize`, refusals only, never for what a feature could state. L4: `write` is total over a design `legalize` accepted (AMEND-A12 S1). | Features are the neutral vocabulary passes act on; a parameter a target lacks has no pass. A silently ignored parameter is a wrong number with no crash, so the check is not optional. |
| R22 | 2026-11-12 | ngspice draws a fresh sample at every reference even in a plain run (`DrawWhen::Always`); VACASK draws only inside `mc`. Refuse the pair? | A pass relabels `Always` to `Sampling` with a note (a plain run then uses the nominal). Per-reference to per-call-site is exact only where the joint distribution is unchanged (a draw-holding parameter read once, or no sampling loop); otherwise refused. | A random plain-run value is the oracle of nothing, so nothing checkable is lost, and every PDK deck that multiplies a draw by a zero switch would otherwise be refused. Where the result is a random variable, equal means equal in distribution. |
| R23 | 2026-11-12 | Element names were stored without their SPICE letter (`IR-KERNEL.md` §6), so `i(vdd)` read as `I("dd")` and a current through `L1` could not be told from one through `V1`. | An element's name is its whole name, unique in its scope across kinds (AMEND-A12, section A13). A name that does not begin with its kind's SPICE letter is a feature (`NameWithoutLetter`) a SPICE-card writer lacks; a pass renames. | Identity is the interned name (REWRITE-PLAN §3.1). One namespace per scope is what Spectre, VACASK and the Python API have; the letter is a spelling rule of four dialects, so it is a feature and a pass, not a field on every reference. |
| R24 | 2026-11-12 | ngspice's state cards (`.options`, `.temp`, `.ic`, `.nodeset`) hold for the whole deck wherever they stand; the IR's state items held only for what follows them. Move them at read, or say it? | Say it: `applies: FromHere \| WholeRun` on `Option`, `Env`, `NodeSet`; among `WholeRun` items that set the same thing the last listed holds (AMEND-A12, A14). A reader whose simulator resolves a conflict another way keeps the winner and reads the loser as an `Inert` opaque. | Moving a card at read is a conversion inside the reader, and across an include it moves text from one file into another, which breaks every other deck that includes that file. A mode keeps reader and writer in place and inverse (R2). |
| R25 | 2026-11-12 | ngspice runs a deck's analyses by type rank, reverse card order inside a type (not "reverse card order": `INV-semantics.md` 8.04 is wrong). Does the IR list analyses in run order? | No: in the source's listed order. Analyses with no `Alter`, loop boundary or `FromHere` state between them are independent; their order changes no number, only the order of results, which is a run fact of the dialect that ran them (S12). | The same deck read and written keeps its card order, so the same simulator does the same thing; nothing is permuted, so nothing can be permuted wrongly. |
| R26 | 2026-11-12 | A run card inside a `.subckt` body (ngspice runs it as the deck's). | A run item is its deck's wherever it stands; `RunExtra::RunItemNested` marks one outside its file's top scope and `If` chains, for a target that rejects it. | It is what the simulator does, and a pass can hoist it for a target that will not take it. |
