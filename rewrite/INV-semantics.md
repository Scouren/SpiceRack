Inventory for the dialect-neutral IR's normal form. Read-only research, 2026-11-11. Nothing here is new research: every row restates what the previous team's dossiers, settle files, ledger and code already record, with its citation.

- `side`: **READ** = the source reader must normalise it into the IR; **WRITE** = the target writer must spell or compensate; **BOTH**; **RUN** = backend/result side, not netlist.

## The normal form in one page (what the rows ask the IR to pin)

These are this inventory's proposals (the last column of each row gathered up), not decisions already taken. The only decided design among them is D16's neutral expression language, named in item 2.

1. **Literals**: one exact f64 in base SI units; no suffix, unit tail or case rule survives (1.01–1.07). The value rule itself is an open choice between "the bit-exact double the source simulator computes" and "the correctly rounded decimal" (1.08).
2. **Expressions**: a typed tree. Distinct nodes for `Pow` (signed real power, stated negative-base rule), `Neg`, `LogicalXor`/`BitXor` (no caret), `Ln`/`Log10`, `Trunc`/`Floor`/`Ceil`, `RoundHalfEven`/`RoundHalfAway`, `Fmod` (dividend's sign), `Select`, `Clamp`, `Ddt`, `Idt(expr, ic)`, `Table1D` (linear, ends held), real-domain functions with stated domain errors; no `pwr`, `pwrs`, `limit`, `if`, `nint`, bare `log` or named constants (2.01–2.22). D16's neutral builder language (DESIGN-neutral-expressions §2) already fixes most of this for Python strings: `**` right-associative, unary minus looser than `**`, `^` refused, comparisons non-associative, nested ternaries parenthesised, `log` natural, `round` half away, `int` truncating, reserved `time`, `temp`, `pi`, no other constants.
3. **Special leaves**: `Temp` (°C), `Tnom`, `Time`, `Freq`; each value slot declares constant / temperature-dependent / dynamic (2.21, 3.04).
4. **Typed values**: Number, Expr, String, Version, flag, absent. Every parameter carries a `given` bit; a default the source would apply is materialised by the reader (2.23, 3.09, 7.13).
5. **Symbols and scope**: interned ids; exactly one definition per (scope, name), the source simulator's winner; explicit formals with defaults; flat, uniquely named definitions that record their owning scope; includes and library sections resolved before the IR (3.01–3.06, 11.05, 11.11).
6. **Deck state**: `temp` and `tnom` explicit in °C; geometry in metres with `scale` applied; options keyed by role (Newton and LTE tolerances, method + order, max step, gmin/gshunt) and tagged equations / accuracy / path-only (4.01, 6.06, 10.01–10.09).
7. **Sources**: three independent slots {dc, ac (magnitude, phase°), transient waveform}; waveforms by formula with named fields, absolute times, explicit t=0 and pre-delay values, explicit cycle and repeat counts; `m` folded; port = {index, z0, EMF}; no `startup` flag (5.01–5.33).
8. **Elements**: a kind enum (never a letter); terminals bound by role; multiplicity a dedicated field composed down the hierarchy; hidden parasitics materialised as elements; capacitor/inductor law explicit (q(v) or c(v); φ(i)); switch law an enum; lines as per-unit-length RLGC matrices plus length (6.01–6.33, 11.03).
9. **Models**: (family, version, polarity) from a closed registry, never LEVEL (today's ruling keeps ngspice's numbering as the neutral level); canonical semantic parameter names; default-complete cards; a module handle {source artifact, define set}; a (family × analysis) capability table (7.01–7.22).
10. **Run plan**: ordered analyses with stable ids over epochs (complete states, no carry-over); typed sweep targets; sweeps as explicit points or {kind, start, stop, number of values}; Tran = {stop, record_start, print_step, max_step, initial_state}; one IC table with precedence applied; MonteCarlo = {runs, seed, scopes, wrapped analyses} over declared random variables with a draw scope (8.01–8.26, 12.01–12.07, 13.01–13.08).
11. **Outputs**: an explicit save set (All / classes / items); probes = (instance path, node), (instance, terminal, sign = positive into the device) or (instance, canonical quantity); structured measures (9.01–9.09).
12. **Results**: keyed by analysis id and canonical probe; each run tagged with its sweep-point values; noise as PSD; harmonic balance as one-sided peak phasors, cosine reference; loop gain as the return ratio T with a pinned sign (15.01–15.10, 8.18).
13. **Obligations**: a reader applies the SOURCE simulator's own rule (first/last wins, ignored words, given-zero defaults, compatibility mode, hidden elements; a line the source rejects gets a P-code and no meaning). A writer never emits a form the target ignores, zeroes or reads differently; otherwise it refuses with a code (14.01–14.13).

## Appendix D. What today's behaviour switches bundle (from the code slice)

The code models most rows above as per-dialect enum variants in `src/syntax/behaviour.rs`. Several enums bundle unrelated MEANINGS under one switch; the IR has to pin each meaning separately:

- `NetlistRules` (Ngspice / Hspice / Xyce / Ltspice / Spice) bundles nine: model `r=` (6.08), X multiplicity (6.01), duplicate parameters (3.01), device IC (8.21), SFFM order (5.01), default TNOM (4.01), zero TSTEP (8.03), `scale` (6.06), `$G_` globals (11.02).
- `ExprEval` (C / Ngspice / Hspice / Xyce / Ltspice) bundles: ternary grouping (2.13), `log` base (2.09), `nint` rounding (2.10), `limit` (2.14), statistical nominal (12.02), quoted-value typing (2.23), `if()` (2.13).
- Power semantics sit in three places: the lexicon operator rows (grouping), `caret_power`, and the law chosen in `render/spice/pair.rs` (2.01–2.05).
- `NumberReading` and the scale tables decide which double a literal is (1.01, 1.08).
- `SourceRules` and `CardRules` decide waveform field counts, PWL relative time, AM order and where `r=`/`td=` may stand (5.03, 5.09, 5.11).
- `IncludeScope` and `subckt_multiplicity` change which definitions and how many copies exist (3.06, 6.01).
- `level_aliases`, `model_masters`, `spice_model_types` are the only statement of which equations a LEVEL means (7.01).
- `option_map` and `OptionsForm` hide that `vntol` and `abstol` are different quantities and that GSHUNT/RSHUNT and GMIN/GMINDC are inverses or splits (10.02, 10.05).
- `Parasitics`, and the `CardRules::Ltspice` path for the implicit `Rser=1m`, hide elements (6.04, 6.05).
- `AnalysisForm` hides run-plan facts: one analysis per LTspice deck, Xyce running only the last card, HSPICE `START=` (8.01, 8.04).
- `EndRule` hides that HSPICE's `.END` ends the run (11.07).
- Pure spelling, no meaning: `Coupling`, `ValueQuoting`, `ParamForm`, `LoadForm`, `Writer`, `NamedRules`, `NamedParams`, `hier_sep`, `temp_name`.

`render/spice/pair.rs` holds one documented field per source→target meaning difference, each with its evidence; it is the densest single statement of these traps in the tree.
