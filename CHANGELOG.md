## Unreleased

- golden: `record` loads each corpus deck's and fixture's kit in the worker that records it, walks the inputs largest first and renders an input of 1 MB or more as one task per target (at most three at once for 32 MB or more); `check-determinism <tree>` renders every input again with its own `GOLDEN_JOBS` and the queue reversed and compares each output's bytes and the MANIFEST with `<tree>`, writing nothing (with no `<tree>` it records into a temp dir first). Measured on the prototype at `61beae9` (research/BUILD-TEST-SPEED.md ranks 1, 2): a record 282.1 s → 42.3 to 46.3 s with 16 jobs, the check 86.7 s with 7 jobs.
- python: a deck is built as ngspice text and written for each backend by the transpiler (`syntax::render`); the IR (`CircuitIR`), its JSON form and the old writers are gone. The store is the deck's source text behind a `* spicerack-source ngspice` line: `to_source()`, `from_source(text, dialect=None)`, `load(path)` on `Subcircuit` and `Testbench`, `Subcircuit.save(path)` and `Testbench.save_source(path)` (`Testbench.save(*outputs)` stays the `.save` card); `to_json`, `from_json`, `save_json`, `load_json` raise `NotImplementedError` naming them.
- python: Spectre-only analyses are Spectre statements in a `simulator lang=spectre` region of the deck's source; `extra_line(line, dialect="ngspice")` is a line of that dialect's text. Each is written for its own dialect family and refused (`W0001`) for any other; nothing is added to a rendered deck. `pss` is Spectre's `pss` statement in that region on a Spectre target and ngspice's `.pss` on every other (the store keeps the `.pss`). `ngbehavior` is an `.options ngbehavior=` card, ngspice's `*spicerack ngbehavior=` line and a `W0030` note elsewhere.
- python: `raw_spice` lines are read as the deck's own statements: each target writes them in its own form (Spectre and VACASK now write them where they refused "raw SPICE line"), and another dialect's text there is refused (`W0001`), not copied.
- python: a `step_sweep(..., "log")` is read from the deck's `.step log` and written as Spectre's `sweep … log=N`; Xyce, LTspice and VACASK refuse it (`W0016`: no total-count log sweep). It was kept as ngspice text, refused (`W0001`) everywhere.
- python: a Spectre `montecarlo` (`add_spectre_monte_carlo`) over one analysis is read from the deck's `spectre` region as an analysis: Spectre writes it as before (now among the analyses), VACASK as an `mc … endmc` loop around the deck's analysis of its inner type (`lh=0`, the seed carried), refused (`W0115`, new) where its `variations` leaves out a scope the deck draws in; SPICE targets refuse it `W0015` (was `W0001`). The VACASK backend reads an `mc` loop's per-sample raw files. The pinned VACASK (`bcd48e2`) has no `mc`.
- python: a refusal is its diagnostic codes and messages (`<deck>:<line>:<col>: W0004 …`), not free text; `nominal_temperature` reaches Spectre in the `options` statement; a `.tran` step cap with no start writes Spectre `start=0` and HSPICE `START=0`; `add_fourier`'s `num_harmonics` is ngspice's `.options nfreqs=` (one count per deck, DC its first frequency), LTspice's `.four` count and Spectre's `harms`, and refused on Xyce and HSPICE, whose `.four` has none.
- verilog: structural Verilog (one module per subcircuit, instances by port name) replaces the old layout's IR `Debug` lines; every other element is a `// W0029` comment.
- python: `Subcircuit.subcircuit(child)` defines `child` inside the subcircuit (a nested `.subckt`, local to it); every target writes it as a top-level `<parent>__<child>`. `Subcircuit.from_source` read a nested definition back as its first line only; it keeps the block.
- python: `C(name, n1, n2, charge="expr")` builds a capacitor given by its charge (ngspice `Q='expr'`); every target writes its own form, VACASK refuses it (`W0105`).
- python: `options()` takes portable keys only (the names of ngspice's `.options`, manual §11.1); `True` writes a bare flag (`klu=True` is `.options klu`, was `klu=True`); `None`, `False` and another simulator's own key raise `ValueError` (were written as text).
- python: `K(name, *inductors, coupling)` takes the two inductors' full names (`K("1", "L1", "L2", coupling=0.9)`); the `inductor1=`/`inductor2=` keywords and the short names (`"1"` for `L1`) are gone (D18).
- backend: a run is routed by every analysis of the deck (was: the first), to a simulator (`backend::Sim`; `select(kinds, …) -> Sim`); a refusal names its cause (the analysis, the feature, or that no simulator runs them all).
- python: `Subcircuit.add_function(name, args, body)` writes a `.func` inside the subcircuit; one reading a parameter of the subcircuit stays local to it (LTspice, Spectre and VACASK refuse it, `W0106`).
- python: `NonLinearVoltageSource` / `NonLinearCurrentSource(name, positive, negative, expression=...)` build the E and G cards `value={expr}` (PySpice's names): the behavioural source of `BV` / `BI` under the E/G letter.
- python: `Testbench.add_spectre_analysis(kind, name=None, nodes=(), **params)` writes any Spectre analysis as its statement (`dcmm3 (out 0) dcmatch mth=0.001`), checked against the analyses Spectre names; a target with no such analysis refuses it (`W0015`).
- python: `Section(name)` builds a library section (`.lib name` … `.endl name`) from `parameter`, `model`, `include`, `lib` and `subcircuit` lines, and `Circuit.section(s)` adds it to a library file a deck's `lib(path, name)` selects from.
- build: pyo3 0.24.2 → 0.27.2, so the extension builds for Python 3.14 (`Python::attach`, `Py<PyAny>` and the two-lifetime `FromPyObject` replace their 0.24 forms); `flake.nix`'s vendor hash follows the lock again; the release workflow builds a 3.14 wheel (ZERO-LEDGER P8-160).
- python: `spicerack.export(results, stem, *, raw_format="binary")` writes a run's results as `<stem>.raw` (one ngspice raw file, every vector under its canonical name) and `<stem>.meas.json` (the `spicerack.measures/1` sidecar: analyses, steps, `.meas` values with their status) and returns the two paths (ZERO-LEDGER P8-100).
- python: `K` couples two or more inductors (one card, every pair), and `coupling` may be an expression (`"{k}"`).
- python: `initial_condition`/`node_set` take an expression value (`out="{vdd/2}"`), and `Subcircuit`/`Circuit` have both, written inside the `.subckt`.
- python: `I`, `G`, `F`, `BV` and `BI` take instance parameters (`m=2`; on a B source also `tc1`, `tc2`, `temp`, `dtemp`), written last on the card.
- python: `ac=`, `ac_phase=` on `V`, `I` and the waveform sources, and a waveform source's `dc=`, take an expression (`ac="{amp}"`).
- python: `Block()` and `conditional(branches, otherwise=None)` on `Subcircuit`, `Circuit` and `Block` write `.if` / `.elseif` / `.else` / `.endif`; a stored subcircuit keeps a conditional whole (`from_source` dropped its branches).
- python: `harmonic_balance` / `add_harmonic_balance` take `num_harmonics` as one count or one per tone, and refuse a list that does not match the tones (it was written as given) and an empty tone list.
- python: `S` and `W` take `initial_state="on"` or `"off"`, the switch's state when its control starts inside the hysteresis band (the card's `ON`/`OFF`; ngspice and ESPice only).
- python: your own simulator. `Simulator(name, dialect=, command=, output=, analyses=, features=, verilog=, verilog_a=)` describes one (checked when built: `R0040`), `register_simulator(sim)` puts it in every route it declares, after the built-ins, `simulators()` lists the names, `load_simulator(path)` reads the descriptor from a `spicerack.simulator/1` TOML file, and a dialect plugin `runs_on` one. A run it cannot take is refused with `W0180` (an analysis it does not declare), `W0181` (a feature), `W0182` (no simulator runs every analysis of the deck) or `R0041` (its program is not on PATH); a process holds 32 simulators (`R0042`). A registered simulator is its command only: what a built-in's run does beyond it is named in `tests/test_simulator_oracles.py::PARITY_SIM_GAP` (ZERO-LEDGER P8-201 … P8-210).
- python: every failure of a netlist, a run or a compile raises `spicerack.Error`, a `RuntimeError` with `.status` (`"refused"`: the deck is not written for the target or no simulator is routed; `"failed"`) and `.diagnostics`, a list of `Diagnostic` (`code`, `kind`, `title`, `cite`, `message`, `line`, `column`, `statement`, `element`); `Testbench.netlist_with_notes(dialect)` returns the deck and its notes as `Diagnostic`s. Texts are unchanged, and `ValueError` stays for a bad argument (ZERO-LEDGER P8-105).
- python: `AmplitudeModulatedVoltageSource`/`CurrentSource` take `signal_phase=` and `carrier_phase=` (degrees; ngspice and ESPice only).
- python: every result lists its `nodes`, `branches`, `measures` and `params` in name order; they came in a hash map's order, another on each result object (`result::Results::nodes` and `branches` are `BTreeMap`s) (ZERO-LEDGER P8-318).
- tools: `spice2rack --to <dialect>` writes that dialect alone (any of the nine), prints the written deck's absolute path on stdout and exits 1 when the dialect refuses the deck (2 on a usage error; an unknown option was read as a deck); `--kit` also writes every file the deck reaches, each `.include`/`.lib` path the absolute path of the written copy under `-o`; `nix build .#spice2rack` builds the converter alone, with no default features (ZERO-LEDGER P1-062).
- python: the distributed lines have builders on `Subcircuit` and `Circuit`: `O` (LTRA), `Y` (TXL), `P` (CPL) and `U` (URC), each the ngspice card with its model (`model(m, "ltra", ...)`); written for ngspice and ESPice only.
- results: a run's measures are the ones its deck names. The line `Stack = 0 bytes.` of ngspice's footer was read as a measure `Stack = 0` in every ngspice result with no `.meas` (and written to `export`'s `.meas.json`), and a `print` of a `.control` block as one too; a `meas` command of a `.control` block is still a measure (ZERO-LEDGER P8-320).
- python: `parameter(name, value)` (`Subcircuit`, `Circuit`, `Section`) takes a number or a `UnitValue` as well as a string, and refuses `None`, a `bool` and an empty string (`ValueError`); the new `Testbench.parameter(name, value)` sets a top-level `.param`, replacing the DUT's parameter of that name (ZERO-LEDGER P8-124).
- python: `spicerack.diagnostics.netlist(testbench, dialect, out_dir, variant)` and `diagnostics.run(testbench, out_dir, variant)` write and run a deck without raising `spicerack.Error` and leave `<variant>.diag.json`, the `spicerack.diagnostics/1` file (`stage`, `status`, the deck's diagnostics located in `<variant>.source.cir`, the `simulator`'s failure), whatever happened; a simulator that exits nonzero is `BackendError::Exited` (its exit status and its whole output, written as `<variant>.log`), where it was a `SimulationError` with the same text (ZERO-LEDGER P8-107).
- syntax: Xyce's `.PREPROCESS REMOVEUNUSED` is applied as the deck is read (the listed kinds' devices on one node are left out) and `.PREPROCESS ADDRESISTORS` is left out with W0023 (Xyce's own run adds no resistor); `REPLACEGROUND TRUE` stays W0039. python: `def_.DotRule.Preprocess` (ZERO-LEDGER P6-014).
